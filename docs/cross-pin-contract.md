# The frozen cross-pin contract (version 1)

Different worktrees and machines of one repo can run different grimoire versions at once: each checkout runs the version its `.grimoire/config.yml` pins. These are the pieces that one version relies on in another. They froze at 1.0.0 (spec §21). **They may only gain fields or ops that older releases ignore**; nothing here is renamed, removed or reshaped, in any release, major or not. `test/release/format-freeze.test.ts` pins the parts that can be pinned. If it fails, read the release promise and the nine rules in the [README](../README.md#for-maintainers) before you touch the expected values.

| Piece | Where it lives | Its shape in version 1 |
| -- | -- | -- |
| The bootstrap string and its argument shape | `src/installer/bootstrap.ts` (`BOOTSTRAP`) | A `node -e` script of about 820 printable ASCII characters, with no `$ " \ % ^` or backtick, so that it runs unchanged under every shell. It walks up from the cwd (or `--from <dir>`) to the first `.git`, follows a `gitdir:` file through `commondir`, and calls `<git-common-dir>/grimoire/launcher.cjs` as `launch(args, root)`. With no launcher, it prints the not-set-up line for `mcp` and `hook session-start`. Entries: `node -e <bootstrap> mcp` (`.mcp.json`, Codex `[mcp_servers.grimoire]`), `node -e <bootstrap> -- --from ${CLAUDE_PROJECT_DIR} hook <event>` (Claude Code hooks, exec form; the `--` is spike A's R3 fix), and `node -e "<bootstrap>" -- hook session-start` (the Codex hook, a command string). |
| The entry verbs | `src/surfaces/launch.ts`, `src/surfaces/entry.ts` | `mcp`, `hook session-start`, `hook pre-tool-use`, and `--from <dir>` before any of them. As v1 tolerance, `hook` exits 0 on an unknown event, and `mcp` ignores unknown flags. |
| `run.cjs pin` | `src/installer/run.cjs` (written to `.grimoire/run.cjs`) | `node .grimoire/run.cjs pin` prints the pinned version and a newline without loading grimoire. It exits 2 with no `config.yml`, and 3 for a pin that isn't strict semver. CI recipes read it. |
| The launcher↔package contract | `src/installer/launcher.cjs`, `src/installer/launcher.ts`, `src/installer/copies.ts` | `<git-common-dir>/grimoire/launcher.cjs` starts with the header line `// grimoire-launcher <version> <sha256 of the rest>` and only moves forward. It exports `launch(args, root)`. A version copy is `pkg/<version>/`, laid out as the package (`package.json`, `dist/`). Its entry is `pkg/<version>/dist/launch.mjs`, exporting `launch(args, info)`. It is complete when `pkg/<version>/.complete` exists: JSON `{"integrity": <npm's tarball integrity or null>, "files": {…}}`, which may gain fields. The launcher reads only that the file exists. |
| The marker schema | `src/tracker/marker.ts`, `src/machine-local/marker.ts` | The tracker's `format` file and `<git-common-dir>/grimoire/format`: one `key: <JSON value>` per line, with `format`, `compat` (integers) and `requires` (the oldest release that can write it). A release runs iff J ≤ `compat` ≤ K. 1.0.0 writes `format: 1`, `compat: 1`, `requires: "1.0.0"`. |
| The join-record schema | `src/installer/records.ts` | `<git-common-dir>/grimoire/records/join/<pin>.json`: `{"excerpt_mode", "codex_hook_hash", "joined_at"}`. The launcher runs a pin only once its join record exists. |
| The coordination class | `src/machine-local/store.ts` and the kinds it serves | Version-free files under `<git-common-dir>/grimoire/`: `leases/<name>/<gen>.json`, `locks/<name>/<gen>.json` (among them the install lock and `start`'s lock, with `{port, nonce}`), `processes/<pid>-<nonce>.json` (process records), and `coordination/<kind>/<key>.json` (seen-here rows, upgrade-in-progress records, the runner counters, `tracker-push` records of pushes under way `{commit, pid, host, expires_at}`, …). No coordination file carries a version field. |
| The control-channel protocol | `src/surfaces/start/control.ts` | Protocol 1: a named pipe `\\.\pipe\grimoire-<clone>-<nonce>` on Windows, or a Unix socket in a 0700 directory elsewhere. One request per connection, one line of JSON each way, authenticated by an HMAC over a per-user secret that never crosses the channel (spike D's R5). The ops are `sign-in` (`{"ref"?}` → `{"url", "port", "version", "pin", "pid"}`) and `stop`. An older `start` answers an unknown op with `UNKNOWN_OP`. |
| The manifest entry kinds | `src/installer/manifest.ts` (`ENTRY_KINDS`) | `.grimoire/manifest.yml` lists every entry grimoire wrote into the checkout, as one of the closed set `file`, `json-key`, `json-array-item`, `toml-table`, `marker-block`, `npm-script` and `seeded-file`. `uninstall` reads only this list (rule 7), and stops before any write on a kind it doesn't know, naming a release that does. |
| The generated-path list | `src/generated/path-list.ts` | `<git-common-dir>/grimoire/records/generated-paths.txt`: every generated skill folder grimoire made in any worktree of the clone, one absolute path per line. `leave` and `uninstall` at any release read it. |

## What `install_format` covers instead

`install_format` is the checkout-side format (`.grimoire/config.yml`): the bootstrap, the hook entries, the permission-bearing entries, which pointer files exist and where, the manifest schema, `run.cjs` and the dotfolder layout. 1.0.0 ships `install_format: 1`. Only a major may bump it, and bumps are batched into majors (rule 6). Shipped text (instruction text, chore carriers, the adapter block, stub bodies) and verb behaviour may change in any release.
